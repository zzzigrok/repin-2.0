# 📉 Mode Collapse: Что это такое и как с этим бороться

## 1. Что такое Mode Collapse?

**Mode** (в статистике) — это локальный максимум в распределении данных. Для датасета MNIST у нас 10 мод — цифры от 0 до 9.

В идеальном сценарии Генератор учится создавать выборку из всего распределения (всех 10 цифр). При **Mode Collapse** Генератор "схлопывается" и учится идеально подделывать только одну (или несколько) мод, полностью игнорируя остальные.

## 2. Почему это происходит?

Это следствие динамики минимаксной игры между Генератором (G) и Дискриминатором (D):
1. Генератор случайно создает хорошую подделку цифры "1".
2. Дискриминатор ошибается и пропускает её.
3. Генератор понимает: *"Ага! Создание единиц — выигрышная стратегия"*.
4. Вместо того, чтобы учиться рисовать другие цифры (что сложно), Генератор начинает рисовать **только единицы**, чтобы гарантированно обманывать Дискриминатора.

## 3. Симптомы и Диагностика

Как понять, что у вас Mode Collapse:
- **Визуально:** Вы генерируете батч из 64 картинок (в меню пункт `2`, затем `64`), и видите, что 90% картинок — это одна и та же цифра с минимальными вариациями.
- **По графикам:** `D_Loss` становится очень высоким (Дискриминатор не может отличить эти идеальные единицы), а `G_Loss` падает почти до нуля (Генератор постоянно выигрывает).

## 4. Как исправить в Repin 2.0?

К сожалению, вылечить уже сколлапсировавшую модель сложно, лучше начать заново. Удалите `repin_weights.pth` и измените гиперпараметры в `cli.py`:

### Способ 1: Изменить Learning Rate
Если Генератор слишком быстро адаптируется, уменьшите его `lr`. Вы можете задать разные `lr` для G и D (TTUR - Two Time-scale Update Rule):
```python
# В cli.py (внутри train_model)
d_optimizer = torch.optim.AdamW(D.parameters(), lr=0.0004, betas=betas, weight_decay=weight_decay)
g_optimizer = torch.optim.AdamW(G.parameters(), lr=0.0001, betas=betas, weight_decay=weight_decay)
```

### Способ 2: Увеличить размер батча (Batch Size)
Маленький размер батча не позволяет Дискриминатору "увидеть" всю картину распределения. Попробуйте увеличить `batch_size`:
```python
batch_size = 256 # вместо 128
```

### Способ 3: Изменить размер латентного вектора (Latent Size)
Увеличение шума заставляет генератор создавать больше вариаций:
```python
latent_size = 100 # вместо 64
```

### Способ 4: Рандомизация (Label Smoothing / Noise)
*(Продвинутый уровень, требует написания кода)*
Вместо того, чтобы говорить Дискриминатору "Это 100% настоящая картинка", скажите "Это настоящая картинка с вероятностью 90%". Это не дает Дискриминатору быть слишком уверенным.

```python
# В cli.py (внутри train_model)
# Вместо ones = torch.ones(...)
ones = torch.empty((b_size, 1), device=device).uniform_(0.9, 1.0)
```
